# TestTool

局域网内用手机遥控电脑截屏，交给 DeepSeek 解答，答案流式回传手机。

```
手机浏览器 ──POST /ask──▶ Node 服务 (PC)
   ▲   (SSE 流式)            ├─ 截屏   PowerShell + System.Drawing
   │                         └─ 解答   DeepSeek deepseek-flash（视觉）
   └──── 答案逐字出现 ◀───────┘
```

---

## 首次准备

```bash
npm install
cp .env.example .env
```

编辑 `.env`，填上 `DEEPSEEK_API_KEY=sk-xxx`（从 platform.deepseek.com 获取）。

## 启动方式一：托盘（推荐）

双击项目根目录的 **`启动 TestTool.lnk`**。

服务在后台跑起来，右下角系统托盘出现一个蓝色图标。不会留下任何黑窗口。

- **双击图标** → 打开网页
- **右键图标** → 弹出菜单

| 菜单项 | 作用 |
|---|---|
| 打开网页 | 在电脑浏览器打开，方便先自测 |
| 复制手机地址 | 把 `http://192.168.0.153:8787/` 复制到剪贴板，好发到手机上 |
| 启动 / 停止服务 | 切换运行状态 |
| 重启服务 | 改过提示词或配置之后用 |
| 打开日志 | 记事本打开 `logs/service.log` |
| 退出 | 停掉服务并移除托盘图标 |

几个行为上的保证：

- **单实例** —— 重复双击只会提示「已经在运行」，不会开出第二个托盘
- **崩溃自动拉起** —— 服务意外退出时 5 秒内自动重启；手动点「停止服务」则不会（它记得你的意图）
- **退出即清理** —— 点「退出」会连 node 子进程一起杀掉，不留孤儿占端口
- **零依赖** —— 用 Windows 自带的 .NET WinForms 实现，不装任何东西

## 启动方式二：命令行

### 开发模式（改代码自动生效）

```bash
npm run dev
```

同时跑两件事：esbuild 监听前端、`node --watch` 监听服务端。改完代码手机刷新页面即可。

### 生产模式（跑起来就用）

```bash
npm start
```

会先自动构建前端，再启动服务。**这个窗口必须一直开着**，关掉服务就停了。

启动后控制台会打印手机访问地址：

```
    手机访问   http://192.168.0.153:8787/
    本机访问   http://127.0.0.1:8787/
    模型       deepseek-flash
    API Key    已配置
    截图保存   E:\学习\前端\TestTool\pics
```

手机访问用的地址在 `LAN_IP` 里固定。没配的时候是自动探测网卡的 —— 装了 VPN、
虚拟机或代理 TUN 的机器上，探测常常挑中那个手机连不上的假地址，所以
`.env` 里的 `LAN_IP=192.168.0.153` 建议保留。配置的地址不在任何网卡上时，
横幅里会多一行 `⚠`，那是 DHCP 把地址换掉了。

**第一次启动时 Windows 防火墙会弹窗，务必点「允许」** —— 点了取消手机就永远连不上，而且不会再提示第二次。

## 后台常驻（可选）

想让它在后台一直跑、开机自动起来，用守护脚本：

```bash
npm run service
```

这个脚本会在服务退出后 3 秒自动重启，日志写到 `logs/service.log`（超过 5MB 自动轮转）。

要在**后台静默运行**（不占窗口）：

```powershell
pwsh -NoProfile -WindowStyle Hidden -File service.ps1
```

### 配置开机自启

用 Windows 自带的任务计划程序。**以管理员身份**打开 PowerShell，执行：

```powershell
$root = 'E:\学习\前端\TestTool'

$action  = New-ScheduledTaskAction -Execute 'pwsh.exe' `
           -Argument "-NoProfile -WindowStyle Hidden -File `"$root\service.ps1`""
$trigger = New-ScheduledTaskTrigger -AtLogOn
$settings = New-ScheduledTaskSettingsSet `
           -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries `
           -RestartCount 3 -RestartInterval (New-TimeSpan -Minutes 1)

Register-ScheduledTask -TaskName 'TestTool' `
  -Action $action -Trigger $trigger -Settings $settings `
  -Description '局域网截屏解题服务'
```

取消自启：

```powershell
Unregister-ScheduledTask -TaskName 'TestTool' -Confirm:$false
```

## 两种作答模式

顶部最左边是模式切换。

### 解题

默认模式。截下屏幕，找出上面的题目并解答。每次都是独立的一问一答，不记历史。

#### 题目截图留档

每次在**解题**模式下提问，截下来的那张图会存一份到项目根目录的 `pics/`：

```
pics/两数之和_2026-10-27_17-50-42.png
```

- 文件名前半截是 AI 概括的一道题简称，后半截是本地时间（精确到秒）
- 简称里的非法字符会被去掉，超过 20 字会截断；AI 没按要求给标题时叫 `未命名_时间.png`
- 撞名时追加 `-2`、`-3`，**不会覆盖**已有的图
- **只存不删**，单张约 0.15–0.3MB，要清理自己开文件夹
- **性格测评模式不存图** —— 那类截图只是用来答题的
- 存图失败不影响答题，日志里会有一行以 `[pics]` 开头

`pics/` 不在网页服务的目录里，手机和浏览器都访问不到，只能从电脑的资源管理器打开。

### 性格测评

给性格／心理测评答题用。和解题模式的根本区别：这里要的不是「答对」，而是
**答得像同一个人** —— 测评方会检测前后矛盾，一份自相矛盾的答卷比一份平庸的答卷更糟。

点开「目标岗位」，填岗位名称，或者**直接粘贴整段招聘要求**。里面的具体措辞
（「抗压」「跨部门沟通」「独立交付」「注重细节」）越具体，作答越贴。

第一次打开会预填一份「普通且细致的一线开发工程师」的画像，刻意写得普通 —— 见下面
「别答得太漂亮」那条，一份全是亮点的画像反而会把答卷推向不真实。改过的内容存在
浏览器里，下次打开以你改过的为准。

服务端会记住这场测评的每一轮作答，下一题发给 AI 时带上，让它自己对照着保持一致。
每题回答里都会有一行 `**倾向**：`，那既是给你看的，也是给下一题的 AI 读的。

几点行为：

- **改完岗位，下一题自动重开一场**，之前的作答不作数（换岗位 = 换一套人格画像）
- 题数**以服务端为准**，页面刷新、手机息屏回来都还是对的
- 会话在服务端内存里存 **30 分钟**，超时或重启服务就没了（手机上「已答 N 题」会归零）
- 「重新开始」= 换一个新会话，从头来
- 解题和性格测评的答案不会互相干扰，切过去再切回来，那场测评还在

#### 提示词在防什么

性格测评不是考试，是匹配度探测。所以这套提示词不追求「答得漂亮」，
而是让整份答卷**看起来像一个真实的、稳定的人**。两条红线：

**一、前后不能矛盾。** 测评方内置交叉验证，被判「不真实」比某个特质「不匹配」
后果重得多 —— 不匹配只是不合适，不真实是整份答卷作废。作答历史就是为这条服务的。

**二、别答得太漂亮。** 社会赞许性检测会盯上「所有正向陈述都同意、量表一路满分」
的答卷，那同样会被判不真实。所以遇到「我从不犯错」这种绝对化的自我表扬，
提示词要求给次强档而不是最强档 —— 真人对自己的评价没这么绝对。

这两条和「贴合岗位」是有张力的：贴得太满就成了「完人档案」。
提示词的做法是**优先保证可信，其次才谈贴合**。

#### 支持的题型

| 题型 | 怎么答 |
|---|---|
| 单选 / 情景判断 | `答案：B` |
| 量表（非常同意…非常不同意） | `答案：比较同意` |
| **强迫选择**（SHL OPQ：挑最像、最不像各一个） | `答案：最像 B / 最不像 D` |
| **能力测试**（北森包里的行测：数量关系、图形推理、言语理解） | 照常给答案和简短解析，「倾向」那行写「—（能力题，不计入画像）」，不污染性格画像 |

北森的测评包是**行测 + 性格混着出**的，所以能力题不用切回解题模式，
在当前模式下直接答就行。

> **为什么历史里不保留截图？** 每次请求都要把整个对话历史重发一遍，图一旦进了历史，
> 那串 base64 就每一轮都要重新上传 —— 第 50 题时光图就有 20MB，而家用宽带上行要为此
> 多等好几秒。历史只留文本的话，第 50 题也不到 2MB。
>
> 一致性因此不靠旧截图，而是靠模型自己写下的那行「倾向」。代价是：**当选项里没有
> 一个干净贴合已有人格的答案时，模型会挑最接近的那个并给出解释** —— 读起来略像找补，
> 但不会前后打架。

## 界面上的其他开关

顶部那一排是：作答模式（解题 / 性格测评）、字号、深度思考。

- **字号**：小 / 中 / 大 三档（80% / 100% / 180%），答案、代码块、思考过程一起缩放；
  选过的档位记在浏览器里
- **深度思考**：让模型先想再答，更慢也更贵

**截屏永远是全屏**，界面上没有范围选择 —— 默认就没人切，留着只是多一个会点错的按钮。
活动窗口那条链路（`capture.ps1 -Mode window`、`captureScreen('window')`）完整保留在代码里，
`http://<ip>:8787/probe?mode=window` 仍然可以直接调用；想恢复按钮只是把 UI 加回去的事。
`/ask` 接口也照旧接受 `mode` 字段，不传或传别的都按全屏处理。

**手机横过来**时顶栏会自动收成一行、按钮变矮，把高度留给答案和代码块；左右也避开
了刘海。竖屏布局不受影响。

## 验证服务是否正常

按这个顺序排查，能把问题隔离开：

| 步骤 | 在哪做 | 通过说明什么 |
|---|---|---|
| 1 | 电脑浏览器开 `http://127.0.0.1:8787/` | 服务端和前端正常 |
| 2 | 电脑浏览器开 `http://127.0.0.1:8787/probe` | 截屏链路正常（返回尺寸 JSON） |
| 3 | **电脑上**点「截屏提问」 | DeepSeek 调用正常 |
| 4 | 手机开 `http://192.168.0.153:8787/probe` | **网络通了**（防火墙没挡） |
| 5 | 手机上点「截屏提问」 | 全链路通 |

第 4 步失败 = 网络层问题，跟代码无关，别去翻代码。

## 常见问题

**手机连不上**

按顺序查：

1. 确认手机和电脑在同一个局域网
2. Windows 防火墙是否放行（Win11 上以太网常被归为 **Public** 配置文件，给 Private 加规则不生效）：
   ```powershell
   Get-NetConnectionProfile                    # 看 NetworkCategory
   Set-NetConnectionProfile -InterfaceIndex N -NetworkCategory Private
   ```
3. 路由器是否开了「AP 隔离 / 客户端隔离」—— 开了的话手机永远连不上电脑

**手机地址变了 / 昨天还能开，今天打不开**

地址本来由路由器 DHCP 分配，换租约就可能从 `192.168.0.153` 变成 `.154`。
`.env` 里的 `LAN_IP` 只是「告诉手机该连哪个地址」，改不了网卡实际拿到的地址。

先看服务横幅有没有那行 `⚠ ... 不在任何网卡上`，再用这个确认现在的真实地址：

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' }
```

想让它长期不变，在路由器里给这台机器做 **MAC 地址绑定 / DHCP 保留**；
只想先恢复使用的话，把 `.env` 的 `LAN_IP` 改成新地址，再重启服务。

**端口 8787 被占用**

多半是上次的服务没退干净。服务启动时会打印清理命令，也可以直接：

```powershell
Get-NetTCPConnection -LocalPort 8787 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

或者换个端口：在 `.env` 里写 `PORT=8788`。

**截屏失败**

- `目标窗口已最小化或不可见` —— 这条只在你手动开 `/probe?mode=window` 时会遇到；
  网页上的「截屏提问」永远走全屏，不会报这个
- 锁屏或远程桌面断开时截屏会失败，这是 Windows 的限制
- 杀毒软件可能拦 `node → pwsh → Add-Type` 的运行时编译，首次卡住先查是否被拦

**改了提示词没生效**

提示词在 [server/prompt.ts](server/prompt.ts)，改完要重启服务。

性格测评模式的提示词没有 `.env` 覆盖入口，这是有意的 —— 岗位是每场测评现填的，
覆盖掉整段提示词等于把岗位一起覆盖没了。

注意：DeepSeek 的硬盘缓存按前缀匹配，**频繁改提示词会让缓存失效**，后续几次请求按未命中价计费（贵 50 倍）。

## 成本

单次调用约 **0.5 ~ 1.1 分钱**（低峰 / 高峰）。详见 DeepSeek 定价页。

几个省钱的点：

- 输出是最贵的部分（单价是输入的 4 倍），保持 thinking 关闭
- 避开北京时间 09:00–12:00 和 14:00–18:00，低峰价减半
- 别频繁改 system 提示词，会破坏缓存

```
├─ server/
│  ├─ server.ts      HTTP 服务 + SSE 转发 + 路由
│  ├─ capture.ps1    截屏脚本（全屏 / 活动窗口 / 裁剪）
│  ├─ capture.ts     spawn pwsh、单飞锁、错误翻译
│  ├─ deepseek.ts    API 调用 + 上游 SSE 分帧解析
│  ├─ pics.ts        解题截图的留档（命名、清洗、写盘）
│  ├─ prompt.ts      两种模式的系统提示词
│  ├─ session.ts     性格测评的作答历史（内存，只存文本）
│  ├─ session.test.ts  会话状态机的回归测试（npm test）
│  └─ pics.test.ts   截图命名的回归测试（npm test）
├─ pics/             解题模式的题目截图（自动创建，不进 git）
├─ web/
│  ├─ app.tsx        React 界面（esbuild 打包）
│  └─ style.css
├─ 启动 TestTool.lnk  双击这个（托盘启动）
├─ tray.ps1          托盘图标 + 右键菜单 + 看门狗
├─ testtool.ico      图标（快捷方式和托盘共用）
├─ start.cmd         备用的命令行启动器
├─ service.ps1       守护脚本（无托盘的常驻方式）
└─ dev.mjs           开发模式：前端 watch + 服务端 watch
```
